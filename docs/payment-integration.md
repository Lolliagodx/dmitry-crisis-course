# Тестовая интеграция платежей

Серверная часть реализована в `payments/`. Инструкции настройки: `payments/README.md`.
Курс: 2900 ₽, email -> ссылка на Google Диск. Консультация: 5000 ₽, имя и телефон -> Telegram.
Реальные платежи программно запрещены; до заполнения приватного config.php тестовые покупки отключены.
Тестовый Shop ID: 1535303. Нужны тестовый ключ, папка курса, SMTP и Telegram-бот.
Ниже — план для будущего рабочего запуска; это не описание включённых продаж.

## Рекомендуемый сервис

ЮKassa: оплата в рублях российскими картами и через СБП на готовой странице сервиса.
Доступные способы нужно подключить в магазине. До подключения выбрать статус
продавца (самозанятый, ИП или организация) и согласовать с сервисом оформление чеков.
Конкретные комиссии и условия проверять при заключении договора.

## Сценарий после запуска

1. Покупатель нажимает «Получить курс», видит цену и условия, вводит email.
2. Сервер создаёт заказ и платёж ЮKassa с уникальным Idempotence-Key.
   Сумма, валюта RUB и идентификатор курса берутся из серверных настроек.
3. Покупатель переходит на платёжную страницу ЮKassa и выбирает карту или СБП.
   Сайт не получает и не хранит данные карты.
4. ЮKassa присылает payment.succeeded на HTTPS webhook сервера.
5. Сервер сам запрашивает платёж по API ЮKassa и проверяет succeeded, paid,
   магазин, test/live, сумму, валюту и соответствие платежа своему заказу.
   Одного содержимого webhook или возврата браузера недостаточно для выдачи.
6. После подтверждения сервер открывает доступ к ссылке и отправляет её на email.
   Повторные уведомления не создают повторных заказов или повторной выдачи.
7. Страница возврата запрашивает состояние заказа с секретным токеном доступа.
   При задержке уведомления показывает ожидание, при отмене — возможность повторить.

## Размещение на Sprinthost

Оставить статический фронтенд. Серверную часть можно реализовать на PHP с SQLite
или MySQL: они доступны на текущем хостинге, отдельный Node.js процесс не нужен.
Хранить заказы, секретный ключ ЮKassa и ссылку на курс вне public_html.
Не помещать ссылку на Google Диск в React, NEXT_PUBLIC_ переменные, GitHub
или общедоступные JSON. Публичный код не должен содержать ключи магазина.

Перед запуском подключить собственный домен и HTTPS. Технический HTTP-адрес
предназначен для просмотра фронтенда; продажи на нём сейчас не включать.

## Что потребуется при возвращении к задаче

- Статус продавца и подключённый магазин ЮKassa.
- Shop ID и сначала тестовый, затем рабочий секретный ключ (настройки сервера).
- Цена курса, состав предложения, данные продавца и согласованные условия продажи.
- Настроенная выдача чеков с учётом статуса продавца.
- Папка Google Диска с подходящими правами доступа.
- Почтовый отправитель и SMTP для писем после оплаты.
- Условия обработки персональных данных и политика возвратов.

Ссылка на общую папку может быть переслана покупателем другому человеку.
Если требуется персональный доступ и отзыв доступа, вместо общей ссылки
добавить выдачу прав на Google-аккаунт покупателя или личный кабинет. Сейчас выбран вариант общей ссылки без дополнительной защиты.

## Проверка перед включением продаж

Проверить в тестовом магазине: успешную оплату, отмену, закрытие вкладки,
возврат раньше webhook, повтор webhook, неправильную сумму, чужой заказ,
поддельный webhook, сбой API, повтор нажатия и повтор отправки письма.
Сбой почты не должен отменять оплаченный заказ: нужна очередь повторной отправки.
Отдельно проверить доступность карты и СБП в подключённом рабочем магазине.
Не включать продажи до завершения этих проверок.

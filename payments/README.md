# Тестовые покупки на Sprinthost

Только тестовый магазин ЮKassa. Ключи без префикса `test_` и платежи с `test != true`
отклоняются. Рабочие платежи не поддерживаются этой версией.

## Установка

- Приватные файлы lib.php, worker.php, config.php и vendor: `/home/davidovd/course-payments/`.
- Скопировать config.example.php в config.php только при первом развёртывании.
- Каталог 0700, файлы 0600. Заказы SQLite, сессии и блокировки создаются здесь же.
- public/checkout.php -> public_html/checkout.php.
- public/payment.php -> public_html/api/payment.php.
- PHPMailer v7.2.0: Exception.php, PHPMailer.php, SMTP.php из официального репозитория
  https://github.com/PHPMailer/PHPMailer/tree/v7.2.0/src
  установить в course-payments/vendor/PHPMailer/src вместе с LICENSE.
- Cron каждую минуту: `/usr/bin/php /home/davidovd/course-payments/worker.php`.
- Тесты: `php test.php` — используют изолированную временную SQLite без сетевых запросов.

## Закрытые настройки config.php

Заполнить shop_id и тестовый secret_key. Для курса: course_url, smtp_host,
smtp_port, smtp_security (ssl/465 либо tls/587), smtp_username, smtp_password,
mail_from, mail_from_name. Для консультации: telegram_token и telegram_chat_id.
Для запуска установить enabled=true. Каждый продукт включается только при наличии
его настроек выдачи. Конфигурация никогда не должна быть в public_html или GitHub.

В кабинете ТЕСТОВОГО магазина → Интеграция → HTTP-уведомления:
`https://xn--h1acejlsg2a1bo.xn--p1ai/api/payment.php?action=webhook`
События: payment.succeeded и payment.canceled.

Проверка готовности без секретов: `/api/payment.php?action=health`.
Формы: `/checkout.php?product=course` и `/checkout.php?product=consultation`.
Формы работают только на каноническом HTTPS-домене. На техническом HTTP-адресе
приём данных и платежей выключен.

## Поведение

Курс 2900 RUB: email до оплаты; после проверенной оплаты — ссылка в браузере
владельца сессии и письмо. Папка Google Диска доступна всем, у кого есть ссылка.
Консультация 5000 RUB: имя и телефон до оплаты; после проверенной оплаты —
сообщение в выбранный Telegram-чат. Email для консультации не запрашивается.
Все исходящие сообщения помечены [ТЕСТ].

Суммы устанавливает сервер. Заказ сохраняется до API-вызова; повтор создания
платежа использует тот же Idempotence-Key и неизменный запрос до 23 часов.
Webhook не доверяет присланному статусу: запрашивается оригинал платежа у ЮKassa,
проверяются ID, metadata.order_id, магазин, сумма, валюта, тестовый режим и paid.
Worker также сверяет незавершённые платежи при потере уведомления.
Секреты и данные покупателей не пишутся в общедоступные логи.

Доставка идёт очередью с блокировкой, повторными попытками и ограничением паузы
до часа. При сбое почты/Telegram оплаченный заказ не теряется. Завершённая отправка
не повторяется. В редком случае сбоя ПОСЛЕ принятия сообщения сервисом, но ДО записи
результата в SQLite повторная доставка возможна (at-least-once); ID заказа в письме
и Telegram позволяет распознать дубль. SMTP не подтверждает попадание во «Входящие».

Данные незавершённых заказов удаляются через 7 дней. Оплаченные тестовые заказы
сохраняются для проверки — удалить/анонимизировать после тестирования по согласованной
политике хранения. База приватная, требуется резервное копирование.

## Перед запуском

1. Пользователь создаёт тестовый магазин, Telegram-бота, запускает его/добавляет в группу,
   получает chat_id; подготавливает папку Drive и SMTP-ящик.
2. Заполняет закрытый config.php; сначала тестирование с собственными контактами.
3. Проверить реальный тестовый платёж, отмену, возврат из ЮKassa, webhook, email и Telegram.
4. Проверить повтор webhook, сбои отправки и работу Cron.
5. Не включать реальные продажи: нужны отдельная реализация live-режима, чеки,
   оферта, реквизиты продавца, политика обработки персональных данных и возвратов.

Политика и реквизиты продавца не выдумываются: текущая форма предназначена
для технической проверки с согласившимися тестировщиками, не для публичных продаж.
